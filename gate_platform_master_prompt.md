## 🎯 PRODUCT VISION & PROBLEM STATEMENT

### The Problem with Existing EdTech:
- Traditional platforms overwhelm students with rigid, minute-by-minute timetables that trigger guilt and cognitive abandonment when missed.
- Practice platforms encourage mindless question spamming rather than deep deliberate practice and structured error analysis.
- Test series provide raw test scores without actionable root-cause diagnostics (Concept Gap vs. Silly Mistake vs. Time Pressure).

### The Solution: "GATE-OS"
A zero-friction, output-driven learning operating system that removes all clock pressure and replaces it with:
1. **The "Rule of 3" Daily Quest System** (Theory Input $\rightarrow$ 15-20 Active PYQs $\rightarrow$ Retention Lock).
2. **The 4-Stage Dependency Skill Tree** (Stage 1 Foundation $\rightarrow$ Stage 2A Circuits/Digital $\rightarrow$ Stage 2B Signals/EDC $\rightarrow$ Stage 3 Analog/Control $\rightarrow$ Stage 4 Comms/EMTL).
3. **The 3-Pass PYQ Solving Arena** with automated 4-minute timer thresholds.
4. **The Automated 3-Line Error Log & Day N+2 Re-Attempt Spaced Queue**.

## 🏗️ SYSTEM SPECIFICATIONS & CORE MODULES

### Module 1: The Daily Quest Dashboard (Zero-Guilt Engine)
- **Zero Clock Timestamps**: The user sees only today's **3 Checkable Quest Cards**:
  - `[ ] 🟢 Box 1: Concept Input` (Embedded video/notes reader with KaTeX math support).
  - `[ ] 🔵 Box 2: Active Problem Solving` (Assigned 15–20 curated PYQs).
  - `[ ] 🟣 Box 3: Retention Lock` (1-page Short Note upload/editor + Error Log submission).
- **Streak & Momentum Protection**:
  - Minimum Viable Day (MVD) toggle: Allows checking 1 box to preserve streaks during emergencies.
  - No retroactive guilt: If a day is missed, the timeline doesn't break; the next card simply slides into active state.

### Module 2: The Interactive 4-Stage Dependency Skill Tree
- An interactive, visual node-graph (built with React Flow / Canvas) displaying all 10 subjects.
- Nodes unlock progressively:
  - **Stage 1 (Locked 28M)**: Engineering Math + General Aptitude.
  - **Stage 2A (Cumulative 44M)**: Network Theory + Digital Circuits.
  - **Stage 2B (Cumulative 56M)**: Signals & Systems + Electronic Devices (EDC).
  - **Stage 3 (Cumulative 68M)**: Analog Circuits + Control Systems.
  - **Stage 4 (Cumulative 78M+ Gross / ~72M Net)**: Communications + Selective EMTL (Transmission Lines).
- Each node displays **Tier 1 (80/20 Golden Topics)** vs **Tier 2/3 (Secondary/Triage Topics)** with completion progress bars.

### Module 3: The 3-Pass PYQ Solving Arena
- Interactive problem interface rendering LaTeX math equations via KaTeX and SVG circuit diagrams.
- **The 4-Minute Timer Engine**:
  - *Pass 1 (0:00 – 3:00)*: Pure solo solving.
  - *Pass 2 (3:00 – 4:00)*: If unsolved, "Formula Peek" unlocks (shows relevant short-note formulas only).
  - *Pass 3 (4:00 – 6:00)*: If still stuck, "Line-1 Hint" reveals the first line of the official derivation.
  - *Timeout (> 6:00)*: Automatically tags question as 🔴 **RED STAR** and pushes it directly into the **Error Log Queue**.
- Instant tagging system: ✅ Green (Solo <3 min) | 🟡 Yellow (Formula assist) | 🔴 Red Star (Pass 3 or Failed).

### Module 4: The 3-Line Digital Error Log & Spaced Re-Attempt Queue
- Form for logging every 🔴 Red Star problem:
  1. **The Trap / Concept Tested** (What trick was missed?).
  2. **My Exact Error & Root Cause** (Categorized: Cat A Concept Gap, Cat B Calculation/Silly, Cat C Time Rush, Cat D Misread).
  3. **The Imperative Rule for Future Self** (One clear directive).
- **Spaced Re-Attempt Algorithm**:
  - The system schedules a **closed-book re-attempt on Day N+2**.
  - If solved correctly $\rightarrow$ Star cleared.
  - If failed again $\rightarrow$ Promoted to **DOUBLE RED STAR ⭕** (high-priority Saturday test review).
- **Error Pattern Analyzer**: Dashboard chart showing weekly mistake distribution (e.g., *"45% of your errors this week were sign errors in Row Reduction"*).

### Module 5: Pixel-Perfect TCS iON CBT Exam Simulator & 5-Step Diagnostic
- **Exact GATE UI Replica**:
  - Left: Question area with MCQ (single correct), MSQ (multiple correct), and NAT (numerical answer with virtual keypad).
  - Right: Question palette (Answered, Not Answered, Marked for Review, Not Visited).
  - Top: Official GATE Virtual Calculator emulator with exact trigonometric, logarithmic, and memory functions.
- **5-Step Automated Post-Exam Diagnostic Dashboard**:
  1. *Score & Accuracy Matrix* broken down by sub-topic.
  2. *Error Taxonomy Breakdown* (A/B/C/D classification).
  3. *Time-Spent vs. Accuracy Scatter Plot* (identifies questions where $>5$ min was wasted).
  4. *Automatic Error Log Population* for all incorrect questions.
  5. *Single-Sentence AI Diagnosis* ("Your main mark leak this test was MOSFET biasing; review Week 7 short notes").

### Module 6: Formula Compendium & Rapid Revision Vault
- Searchable, high-density formula cards rendered with KaTeX.
- Flashcard mode with spacebar flipping and confidence ratings (Easy, Medium, Hard).
- One-click export to printable PDF / Markdown.

## 🗄️ DATABASE SCHEMA SPECIFICATION (POSTGRESQL / PRISMA)

```prisma
model User {
  id            String         @id @default(uuid())
  email         String         @unique
  name          String?
  targetScore   Int            @default(650)
  currentStage  Int            @default(1)
  streakDays    Int            @default(0)
  quests        DailyQuest[]
  errorLogs     ErrorLog[]
  testAttempts  TestAttempt[]
  createdAt     DateTime       @default(now())
}

model DailyQuest {
  id            String         @id @default(uuid())
  userId        String
  dayNumber     Int            // 1 to 126
  stage         Int            // 1, 2, 3, 4
  subject       String
  topicName     String
  theoryDone    Boolean        @default(false)
  pyqsDone      Boolean        @default(false)
  pyqTarget     Int            @default(20)
  pyqCompleted  Int            @default(0)
  retentionDone Boolean        @default(false)
  isMVD         Boolean        @default(false) // Minimum Viable Day
  completedAt   DateTime?
  user          User           @relation(fields: [userId], references: [id])
}

model Question {
  id            String         @id @default(uuid())
  subject       String
  chapter       String
  tier          Int            // 1 (Golden 80/20), 2, 3
  type          String         // MCQ, MSQ, NAT
  marks         Int            // 1 or 2
  year          Int
  branch        String         // EC, EE, IN, CS
  contentLatex  String
  optionsJson   Json?
  correctAnswer String
  solutionLatex String
  hintLine1     String?
  formulaShort  String?
  errorLogs     ErrorLog[]
}

model ErrorLog {
  id            String         @id @default(uuid())
  userId        String
  questionId    String
  trapConcept   String
  myErrorReason String
  category      String         // CONCEPT_A, SILLY_B, TIME_C, MISREAD_D
  ruleForFuture String
  status        String         // RED_STAR, DOUBLE_RED_STAR, CLEARED
  nextReviewAt  DateTime       // Day N+2
  user          User           @relation(fields: [userId], references: [id])
  question      Question       @relation(fields: [questionId], references: [id])
  createdAt     DateTime       @default(now())
}

model TestAttempt {
  id            String         @id @default(uuid())
  userId        String
  testName      String
  testType      String         // SUBJECT_TEST, SECTIONAL, FULL_MOCK
  totalMarks    Float
  scoreObtained Float
  accuracyPct   Float
  timeSpentSec  Int
  answersJson   Json
  diagnosisText String?
  user          User           @relation(fields: [userId], references: [id])
  createdAt     DateTime       @default(now())
}
```
